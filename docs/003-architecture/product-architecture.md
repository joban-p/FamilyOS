# Product Architecture

FamilyOS is organised around life, not software modules.

Users should not need to decide where information belongs. The system should understand context and connect related information automatically.

## Primary Navigation

The primary navigation should remain stable:

- Today
- Calendar
- Money
- Family
- More

## Core Surfaces

### Today

The daily surface. Shows what matters now, what needs action, and what can wait.

### Inbox

The universal capture surface. Everything enters FamilyOS here.

### Calendar

The shared timeline for household life.

### Money

The financial control centre for household income, expenses, bills, goals, assets, and liabilities.

### Family

The people, relationships, care, roles, permissions, and responsibilities layer.

## Global Capabilities

- Global capture
- Global search
- Notifications
- AI assistant
- Permissions
- Offline mode
- Widgets
- Share extension

## Architectural Principle

FamilyOS should feel like one connected system, not a collection of separate tools.
